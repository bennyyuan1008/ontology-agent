## 2. 关键决策与踩坑记录（面试弹药）

| 决策 | 理由/结论 |
|---|---|
| **报表口径主表是 DCP_SALE 而非 DCP_ORDER** | 报表 SQL 显示 0102/0104 用 dcp_sale（202万行），dcp_order（24.9万）只是订单子集 → 对象模型 v2 重映射 |
| **存在两套表体系** | 老版 td_*/ta_*（0101 报表）与新版 dcp_*（0102/0104）并存 → 以 dcp_* + 报表口径为准 |
| **NCHAR 字符集问题** | thin 模式读 NVARCHAR2 报 DPY-3012 → 引擎按 db_type 自动 `CAST(... AS VARCHAR2(4000))` |
| **标量子查询不能进 GROUP BY**（ORA-22818/00979） | 名称类属性（店名/品类名）改为"GROUP BY 主键 + 名称子查询进 SELECT"，属性加 `group_key` |
| **时间字段是字符串** | DCP_SALE.BDATE 为 YYYYMMDD 字符串 → `TO_CHAR(TO_DATE(...))` 转 YYYY-MM-DD，字符串比较 |
| **LangGraph 暂缓** | 沙箱 pip 网络损坏、依赖树重；手写状态机零依赖当日跑通。**代码为节点化结构，可 1:1 移植 StateGraph**（v2 可选） |
| **评测"语义等价"判定** | 忽略 order_by、filters 顺序无关、结果行序无关 → 避免把合理方差误判为错 |
| **数据质量发现** | 2026-04 起销售数据断档 → 评测基准月定为 2026-03（最新完整月） |

## 3. 架构（当前实现）

```
用户提问 → ①意图识别(规则) → ②Ontology规划(LLM→JSON) → ③确定性翻译(引擎→SQL)
        → ④安全校验 → ⑤只读执行(Oracle) → ⑥结果回答
        执行失败 → 带错误信息回退重规划(≤2次)
```

- LLM 只做语义理解（选对象/算子），SQL 由确定性代码生成——口径锁死在对象定义层
- 对象模型不暴露 PII（手机号/身份证）→ 天然安全边界（评测含真实拒绝用例）

## 4. 评测方法论（已落地）

- **设计集/盲测集分离**：`run_eval.py`（设计）与 `--blind`（盲测）分别报指标
- **覆盖矩阵**：`--coverage` 输出 对象×类别×算子 频次，找覆盖空洞（当前缺口：无 AVG/MIN、Product/Store 未被直接查询）
- **盲测池生长**：真实新问题随时入 `eval/blind_pool.json`（先定义期望答案）
- **纪律**：盲测只测不改；一次只改一个变量；迭代日志记录

## 8. 快速开始（当前可用命令）

```powershell
cd ontology-agent   # 项目根目录
py run_agent.py --question "2026年3月销售额最高的5家门店？"   # 自然语言查询
py run_eval.py          # 设计集评测
py run_eval.py --blind  # 盲测池评测（样本外）
py run_eval.py --coverage  # 覆盖矩阵
py gen_eval.py          # 重新生成设计集黄金基准（需连库）
py gen_blind.py         # 重新生成盲测池黄金基准（需连库）
```
